# Установка и настройка «Ищейки»

Документ рассчитан на человека, который видит систему впервые. Все команды
приведены целиком, все пути — реальные.

---

## Что вообще устанавливается

«Ищейка» — **серверная** система. Анализ ведут тринадцать агентов на сервере,
а пользователь работает через браузер. Отсюда три способа установки:

| Способ | Кому | Что получает пользователь |
|---|---|---|
| **Windows-программа** | аналитику на свой компьютер | Двойной клик — открывается браузер с системой |
| **Сервер для отдела** | администратору | Один сервер, к нему подключаются все |
| **Приложение для Android** | аналитику в поле | Клиент к уже поднятому серверу |

Android-приложение **не работает само по себе**: это клиент, которому нужен
адрес сервера. Сначала поднимите сервер (способ 1 или 2), потом ставьте APK.

---

## Способ 1. Windows-программа (самый простой)

### Установка

1. Скачайте из репозитория папку `installers/Ищейка-windows.zip`
2. Распакуйте в любое место, например `C:\Ищейка`
3. Запустите `Ищейка.exe`

Python и другие компоненты ставить не нужно — они внутри программы.

При первом запуске:
* рядом с программой появится файл настроек `.env`;
* откроется браузер по адресу `http://127.0.0.1:8123`;
* в окне программы будет видно, что происходит.

**Окно программы закрывать нельзя** — в нём работает сервер. Свернуть можно.

### Первый вход

Зарегистрируйте пользователя прямо на открывшейся странице. **Первый
зарегистрированный получает права администратора** — иначе в свежей установке
некому выдавать права остальным.

### Включение реального анализа

Без ключа модели система работает на заглушке: отчёты будут демонстрационными
и помечены красной плашкой. Чтобы включить настоящий анализ:

1. Получите бесплатный ключ (2 минуты, банковская карта не нужна):
   * **console.groq.com** → вход через Google → API Keys → Create
2. Откройте файл `.env` рядом с программой блокнотом
3. Впишите ключ в строку `GROQ_API_KEY=`
4. Перезапустите программу

```ini
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_ваш_ключ_сюда
```

Поисковые движки ключей не требуют и работают сразу.

### Где лежат данные

Всё рядом с программой:

```
C:\Ищейка\
    Ищейка.exe          программа
    .env                настройки
    sleuth.db           база данных: миссии, отчёты, память
    storage\reports\    готовые отчёты в HTML, DOCX, PDF
```

Для переноса на другой компьютер достаточно скопировать всю папку.
Для резервной копии — файл `sleuth.db` и папку `storage`.

## Способ 2. Сервер для отдела

Подходит, когда системой пользуются несколько аналитиков.

### Что нужно

* Windows или Linux, 4 ГБ памяти, 10 ГБ на диске
* Python 3.11 или новее
* Выход в интернет (к поисковым базам и провайдеру модели)

### Установка

```bash
git clone https://pio.amg-bs.ru/user1/ischeyka.git
cd ischeyka/backend

python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux

pip install -r requirements.txt
copy .env.example .env          # Windows
cp .env.example .env            # Linux
```

Впишите ключ модели в `.env` (см. раздел «Настройка» ниже) и запустите:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8123
```

`--host 0.0.0.0` обязателен: без него сервер отвечает только сам себе
и коллеги подключиться не смогут.

Проверка: откройте `http://адрес-сервера:8123` с другого компьютера.

### Автозапуск на Windows

Создайте файл `start.bat` рядом с проектом:

```bat
@echo off
cd /d C:\ischeyka\backend
call .venv\Scripts\activate
uvicorn app.main:app --host 0.0.0.0 --port 8123
```

Положите ярлык на него в автозагрузку либо заведите задачу в «Планировщике
заданий» с запуском при старте системы.

### Автозапуск на Linux (systemd)

Файл `/etc/systemd/system/sleuth.service`:

```ini
[Unit]
Description=Ищейка
After=network.target

[Service]
WorkingDirectory=/opt/ischeyka/backend
ExecStart=/opt/ischeyka/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8123
Restart=always
User=sleuth

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now sleuth
sudo systemctl status sleuth
```

## Способ 3. Приложение для Android

**Сначала поднимите сервер** одним из способов выше и узнайте его адрес
в сети — например `192.168.1.50:8123`. Проверьте, что этот адрес открывается
в браузере телефона: если не открывается, приложение тоже не подключится.

### Установка

1. Скопируйте на телефон файл `installers/Ищейка-0.1.0.apk`
2. Откройте его в файловом менеджере
3. Android спросит разрешение на установку из неизвестного источника —
   разрешите (приложение распространяется внутри компании, а не через
   Google Play)
4. Запустите «Ищейку», введите адрес сервера и нажмите «Подключиться»

Адрес запоминается: при следующем запуске система откроется сразу.
Чтобы сменить сервер, очистите данные приложения в настройках Android.

### Требования

* Android 7.0 или новее
* Телефон в одной сети с сервером (или доступ через VPN)

### Почему приложение такое простое

Весь анализ идёт на сервере, телефону остаётся показать интерфейс. Смысл
отдельного приложения — в том, что адрес сервера сохранён и система
открывается одним касанием, без набора адреса в браузере.

## Настройка

Все настройки — в файле `.env`. Он создаётся из `.env.example` и в репозиторий
не попадает: в нём ключи.

### Ключи моделей: сколько и зачем

Свободные тарифы ограничены **посуточно**, причём квота у каждого провайдера
своя. Один ключ Groq — это примерно **шесть полных миссий в сутки**. Поэтому
имеет смысл завести все три бесплатных ключа: система сама переключается
на следующий, когда квота предыдущего исчерпана.

```ini
LLM_PROVIDER=groq
LLM_FALLBACK_PROVIDERS=gemini,openrouter

GROQ_API_KEY=gsk_...          # console.groq.com  → API Keys
GEMINI_API_KEY=...            # aistudio.google.com/apikey
OPENROUTER_API_KEY=sk-or-...  # openrouter.ai/keys
```

Ни один из трёх не требует банковской карты.

| Провайдер | Свободный тариф | Замечание |
|---|---|---|
| Groq | 8 000 токенов/мин, 200 000/сутки на модель | Самый быстрый |
| Google Gemini | ~1 500 запросов в сутки | Щедрее по суточному лимиту |
| OpenRouter | модели с суффиксом `:free` | Лимит строже |

Проверить настройку:

```bash
cd backend
.venv\Scripts\python tools_check_llm.py
```

Скрипт отвечает на два вопроса: доходит ли запрос до модели и умеет ли она
отдавать строгий JSON. Второе критично — на JSON держатся все тринадцать агентов.

### Поисковые движки

Работают **без ключей** и настройки не требуют:

```ini
SEARCH_ENGINES=openalex,crossref,arxiv,pubmed,semanticscholar,duckduckgo,patents
OPENALEX_MAILTO=почта@компания.ru   # необязательно, повышает приоритет запросов
```

Общий веб-поиск через DuckDuckGo нестабилен — его ограничивает антибот-защита.
Для новостей, рыночных отчётов и сайтов производителей нужен ключ:

```ini
GOOGLE_CSE_KEY=...      # console.cloud.google.com, 100 запросов/сутки бесплатно
GOOGLE_CSE_CX=...       # идентификатор поисковой системы
```

Либо свой инстанс метапоиска SearXNG в вашей сети:

```ini
SEARXNG_INSTANCES=http://searxng.внутренний:8080
SEARCH_ENGINES=openalex,crossref,arxiv,pubmed,semanticscholar,searxng,patents
```

### Режимы работы и время миссии

| Режим | Агентов | Время на свободном тарифе |
|---|---|---|
| `quick` | 6 | ~2 минуты |
| `risk` | 10 | ~4 минуты |
| `forecast` | 8 | ~3 минуты |
| `comprehensive` | 13 | 5–8 минут |

Время определяется не мощностью сервера, а лимитом токенов в минуту
у провайдера. На платном тарифе полная миссия укладывается в полторы минуты.

### Прочие настройки

```ini
CACHE_TTL_SECONDS=3600      # кэш поиска и ответов модели; 0 — выключить
MISSION_TIMEOUT=1800        # предельное время миссии, секунды
AGENT_TIMEOUT=300           # предельное время одного агента
MAX_CONCURRENT_AGENTS=8     # сколько агентов работают одновременно
RATE_LIMIT_PER_MINUTE=100   # ограничение запросов к API на клиента
DATABASE_URL=sqlite+aiosqlite:///./sleuth.db
```

Для нагрузки в десятки одновременных сессий SQLite заменяется на PostgreSQL:

```ini
DATABASE_URL=postgresql+asyncpg://sleuth:пароль@localhost:5432/sleuth
```

## Как пользоваться

1. **Войдите.** Первый зарегистрированный пользователь становится администратором.
2. **Поставьте задачу.** В поле «Готовые формулировки» есть образцы по вашим
   направлениям — телеком, ИТ, автоматизация, связь, искусственный интеллект,
   интернет вещей, цифровые двойники, энергообеспечение. Можно взять образец
   и переписать под себя.
3. **Приложите документы**, если есть свои материалы: технические отчёты,
   спецификации, статьи. Текст из них идёт агентам наравне с найденными
   источниками, а сам документ попадает в перечень источников отчёта.
4. **Выберите режим и горизонты прогноза.** Для первого знакомства достаточно
   `quick`.
5. **Наблюдайте за работой.** В журнале видно, какой агент что делает, какие
   замечания нашёл критик, какие противоречия обнаружены.
6. **Изучите отчёт** — HTML в браузере, DOCX и PDF для рассылки.
7. **Проверьте выводы.** Каждое утверждение можно принять или отклонить.
   Отклонённое стирается из памяти системы, чтобы не всплыть в следующей
   миссии как «результат прошлого исследования».

## Что делать, если

**Программа закрывается сразу после запуска.** Запустите её из командной строки
(`cmd`, затем перейдите в папку и наберите `Ищейка.exe`) — увидите причину.
Чаще всего это занятый порт: программа сама возьмёт следующий свободный,
но если заняты все двадцать подряд, освободите их.

**Отчёт помечен «демонстрационный режим».** Ключ модели не задан или неверен.
Проверьте `.env` и запустите `tools_check_llm.py`.

**Агенты падают с ошибкой про лимит.** Суточная квота исчерпана. Впишите ключи
Gemini и OpenRouter — система переключится на них автоматически. Квота Groq
восстанавливается в течение суток скользящим окном.

**Поиск ничего не находит.** Проверьте `/api/v1/health` — там видно, какие
движки подключены. Если в журнале «DuckDuckGo отклонил запрос антибот-защитой»,
это ожидаемо: научные базы при этом работают, а для общего веб-поиска нужен
ключ Google CSE.

**Патентов не найдено.** Так и есть: патентный поиск сейчас идёт обычным
веб-поиском и упирается в ту же антибот-защиту. Нужен ключ USPTO PatentsView
или Espacenet OPS.

**Приложение на Android не подключается.** Откройте адрес сервера в браузере
телефона. Не открывается — дело в сети (телефон в другой подсети, закрыт порт
в брандмауэре), а не в приложении.

**Отчёт в PDF не сформировался.** Система пробует три способа по очереди:
WeasyPrint, браузер Chrome или Edge, встроенный ReportLab. Последний работает
всегда, но вёрстка проще. HTML и DOCX формируются независимо.

## Сборка из исходников

### Windows-программа

```bash
cd backend
.venv\Scripts\activate
pip install pyinstaller
python -m PyInstaller sleuth.spec --noconfirm --clean
```

Результат — папка `backend/dist/Ищейка`. Её и раздают пользователям.

### Android-приложение

Нужны JDK 17 или новее и Android SDK (проще всего — установить Android Studio).

```bash
cd mobile
# укажите путь к SDK прямыми слэшами:
echo sdk.dir=C:/Users/ИМЯ/AppData/Local/Android/Sdk > local.properties
gradle assembleRelease
```

APK окажется в `mobile/app/build/outputs/apk/release/`.

**Важно:** инструменты Android не работают, если путь к проекту содержит
кириллицу — сборка падает с «Invalid file path». Копируйте проект в каталог
с латинским именем, например `C:\build\sleuth-mobile`.

Приложение подписано отладочным ключом: оно устанавливается на телефоны,
но не годится для публикации в Google Play. Для магазина нужен свой ключ
подписи (`keytool -genkey`) и настройка `signingConfigs` в
`mobile/app/build.gradle`.

## Проверка работоспособности

```bash
cd backend
.venv\Scripts\python -m pytest tests\ -q      # 37 автотестов
.venv\Scripts\python tests\e2e_check.py       # сквозной прогон без интернета
.venv\Scripts\python tools_check_llm.py       # проверка провайдера модели
```

Состояние работающей системы: `http://адрес:8123/api/v1/health` — активный
провайдер, модель, подключённые движки поиска, статистика кэша.
