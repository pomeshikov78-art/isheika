# Архитектура «Ищейки»

Документ фиксирует принятые инженерные решения и их причины. Формальные требования —
в [ТЗ-Ищейка.txt](ТЗ-Ищейка.txt).

## 1. Слои

```
HTTP / WebSocket
   └── main.py            API Gateway: JWT, rate limiting, аудит, маршрутизация
        └── api/          контракты REST и поток событий
             └── core/    Mission Core: планировщик → DAG → оркестратор
                  └── agents/    W01–W13, единый контракт execute(context) → result
                       ├── llm/       адаптер провайдеров
                       ├── search/    поисковый шлюз
                       ├── analytics/ S-кривые, риски, уверенность
                       └── memory/    долговременная память
                  └── report/   HTML → DOCX → PDF
```

Зависимости направлены строго вниз: агент не знает об HTTP, шлюз не знает об агентах,
аналитика не знает ни о чём, кроме чисел. Это позволило покрыть аналитическое ядро
тестами без базы, сети и LLM.

## 2. Ключевые решения

### 2.1. Числа считает код, а не модель

LLM извлекает из источников факты и временные ряды, но **не** экстраполирует, **не**
считает уровень уверенности и **не** нормализует риски. Причины:

* модель выдаёт правдоподобные, но невоспроизводимые числа — при повторе прогона они меняются;
* на вопрос «какова твоя уверенность» модель почти всегда отвечает 0.8–0.9 независимо
  от того, что реально нашлось.

Поэтому S-кривая подгоняется в `analytics/scurve.py`, уверенность собирается из пяти
измеримых факторов в `analytics/confidence.py`, а вероятности рисков нормализуются
в `analytics/risks.py` (там же чинится частая ошибка модели — вероятность в процентах
вместо доли).

### 2.2. Уверенность нельзя завысить

Уровень достоверности складывается из качества источников (0.30), их количества (0.15),
независимости доменов (0.20), согласованности агентов (0.20) и свежести данных (0.15),
после чего снижается штрафом за замечания критика, силу контраргументов Red Team и
неразрешённые противоречия. Дополнительно уверенность каждого агента ограничена сверху
объёмом найденного: два источника не дают права на 0.9.

### 2.3. Жёсткие зависимости отделены от порядка выполнения

`DEPENDENCIES` задаёт порядок в DAG («дождись, если агент участвует»), `REQUIRES` —
обязательность входа («без этого работать невозможно»). Смешение этих понятий приводило
к тому, что режим `quick` разворачивался во все 13 агентов: замыкание по мягким рёбрам
затягивало критика, а через него — весь состав.

### 2.4. Отказ одного компонента не роняет миссию

* Движок поиска упал — шлюз логирует и продолжает с остальными.
* Агент упал — после трёх попыток миссия идёт дальше, а факт отказа попадает в отчёт
  как нерешённый вопрос.
* Планировщик не смог разобрать ответ модели — используется безопасный план по умолчанию.
* Рендеринг DOCX или PDF сорвался — JSON и HTML отчёта остаются в силе.
* Память недоступна — это вспомогательный контур, миссия не прерывается.

Единственный по-настоящему фатальный отказ — Finalizer (W13) не собрал отчёт.

### 2.5. Дедупликация как сигнал, а не только экономия

Источники схлопываются по нормализованному URL (без схемы, `www`, tracking-параметров
и якоря), но список нашедших движков сохраняется. Подтверждение из нескольких независимых
каналов повышает надёжность источника у W08 и независимость у W11.

### 2.6. Авторитетность источника

`search/authority.py` содержит таблицу известных доменов и классов суффиксов. Неизвестный
домен получает нейтральные 0.5 — незнание не равно недостоверности. W08 корректирует
базовую оценку по типу документа, наличию DOI, дате и числу подтверждений, но суммарная
надбавка ограничена +0.15: иначе любой источник с DOI и свежей датой вытягивался к потолку,
и различать издателей становилось невозможно.

`doi.org` оценён в 0.72, а не выше: это резолвер ссылок, за которым может стоять
любой издатель.

### 2.7. Экспорт PDF: почему не xhtml2pdf

xhtml2pdf был первым выбором как чисто pip-овая замена WeasyPrint, но проверка показала:
на Windows он не может передать TTF-шрифт в reportlab, поэтому создаёт файл, в котором
вся кириллица напечатана пустыми плашками. Формально экспорт «успешен», фактически
документ нечитаем — это хуже честного отказа, потому что дефект не виден ни по коду
возврата, ни по размеру файла.

Принятая цепочка: WeasyPrint (если установлен) → headless-браузер Chrome/Edge
(печатает ровно тот HTML, что видит пользователь) → ReportLab с явной регистрацией
шрифта DejaVu (простая вёрстка, но кириллица гарантирована). Пустой файл от сорвавшегося
рендеринга удаляется, чтобы API не отдал 0 байт вместо честного «формат не сформирован».

### 2.8. Память

Перед декомпозицией планировщик ищет похожие завершённые миссии, после финализации
W13 сохраняет выводы, факты, риски, базовые сценарии и рекомендации. Эмбеддинги по
умолчанию локальные (`hash`): хеширование слов и суб-словных триграмм даёт устойчивость
к русской морфологии и не требует ключей. При наличии ключа переключается на Qwen/OpenAI.

### 2.9. Релевантность важнее авторитетности

Первая версия шлюза ранжировала выдачу по авторитетности и числу подтвердивших
движков — и в топ выходили цитируемые работы не по теме: на запрос об
аккумуляторах поднимались обзоры по биржевым прогнозам, потому что план
содержал общий запрос «technology review». Авторитетный источник не по теме
хуже среднего, но по теме.

Теперь первый критерий сортировки — соответствие запросу (`search/relevance.py`).
Две тонкости, каждая из которых была реальной ошибкой:

* **Длина префикса словоформы.** На пяти символах «электронного» совпадало
  с «электромобилей», и статья про обучение языкам выходила в топ. Восемь
  символов различают их, но сохраняют «аккумуляторов» ≈ «аккумуляторные».
* **Двуязычность.** Сравнение с одним общим мешком слов давало ноль
  англоязычной статье точно по теме, если запрос был русским. Оценка считается
  по каждой формулировке плана отдельно, берётся максимум.

Формулировки из одной служебной обвязки («technology review», «market forecast»)
отбрасываются: по ним релевантен кто угодно.

### 2.10. Авторитетность: издатель и цитируемость

Ссылка вида `https://doi.org/10.1038/...` не показывает издателя — домен
резолвера одинаков и для Nature, и для любого другого журнала. Издатель
определяется по префиксу DOI (`10.1038` → Nature, `10.1109` → IEEE и так далее).

Цитируемость приходит от OpenAlex, Crossref и Semantic Scholar; ТЗ 5.5 прямо
называет её среди критериев авторитетности. Шкала логарифмическая: разница
между 0 и 50 ссылками значима, между 2000 и 5000 — уже нет.

Надбавки работают **в остатке до единицы**, а не складываются с базой:
`score = base + (1 - base) × (0.4 × метаданные + 0.6 × цитируемость) − штрафы`.
Аддитивная схема с общим срезом упиралась в потолок раньше, чем цитируемость
успевала на что-то повлиять: у крупного издателя база уже 0.90, и любое число
ссылок меняло ровно ноль.

Препринты (arXiv, bioRxiv, SSRN) надбавку за рецензирование не получают —
иначе свежий препринт обгонял статью в журнале только за счёт даты.

### 2.11. Ограничение бесключевого веб-поиска

DuckDuckGo при частых запросах отвечает антибот-заглушкой с кодом 200/202. Первая
реализация принимала её за пустую выдачу и молча возвращала ноль результатов — система
считала, что по запросу просто ничего не нашлось. Теперь заглушка распознаётся по
маркерам, выполняется повтор с паузой, затем отказ поднимается наверх и логируется.
Гарантировать полноту поиска (ТЗ 3.8) бесключевыми средствами нельзя; для эксплуатации
нужен ключевой движок.

### 2.12. Работа на бесплатном тарифе LLM

Бесплатные тарифы ограничивают не число запросов, а **токены в минуту**: у Groq
это 8000 TPM. Миссия из тринадцати агентов тратит около 30 000 токенов, поэтому
без учёта бюджета половина агентов падала с 429 — в одном из прогонов так
потерялся судья W12, и отчёт остался без синтеза.

Ограничение параллелизма задачу не решает: два агента подряд с большими
промптами выбирают минутный лимит так же быстро, как восемь одновременно.
Считать нужно именно токены — этим занят `llm/ratelimit.py`:

* скользящее окно на 60 секунд, перед запросом резервируется оценка стоимости,
  после ответа резерв заменяется фактическим расходом из `usage`;
* фактический лимит система узнаёт из заголовка `x-ratelimit-limit-tokens`
  ответа провайдера и подстраивается сама;
* оценка ответа берётся не по `max_tokens`, а по типичному размеру (900 токенов).
  Резервирование полного потолка раздувало бюджет втрое, агенты стояли в очереди
  и выбивали собственный таймаут.

Следствие для сроков: на бесплатном тарифе полная миссия занимает 5–8 минут
против требуемых ТЗ 9 пяти. Это ограничение тарифа, а не архитектуры: на платном
ключе тот же конвейер укладывается в полторы минуты.

### 2.13. Язык отчёта

Источники по технологиям почти всегда англоязычные, и без явного указания модель
уходит на язык источников: на русский запрос приходил отчёт целиком на английском.
Каждому агенту в системный промпт добавляется директива языка, выведенная из языка
запроса миссии (`agents/base.py`, `language_directive`).

### 2.14. Временной ряд для S-кривой берётся из данных, а не у модели

ТЗ 5.3 требует строить тренды «на основе динамики публикаций». Первая реализация
просила временной ряд у модели — и получала пустой список: в научных статьях
таких таблиц нет. Теперь ряд запрашивается у OpenAlex одним запросом с
`group_by=publication_year` — это фактические счётчики, воспроизводимые и
проверяемые. Текущий год отбрасывается: он не закончился, и его неполный счётчик
выглядит как обвал тренда. Формулировки перебираются по очереди с приоритетом
латиницы: по русскому названию технологии выборка на порядок беднее.

### 2.15. Документы пользователя — такой же источник

Загруженный документ становится полноправным источником: он попадает
в `collected_sources()`, а значит и в перечень источников отчёта. Иначе факт,
взятый из документа, нарушал бы требование ТЗ 3.4 о ссылке на источник
у каждого утверждения.

Надёжность такого источника — нейтральные 0.6: система не может оценить его
ни рецензированием, ни цитируемостью. Завышать оценку только потому, что файл
принёс пользователь, было бы нечестно.

В промпт документ идёт отдельным блоком с бóльшим лимитом символов, чем
поисковый сниппет, и агент обязан ссылаться на него как `[Д1]`. Скан без
текстового слоя не замалчивается: в выжимке прямо написано, что нужен OCR,
иначе пользователь решит, что документ учтён.

### 2.16. Human-in-the-loop: отклонённый вывод стирается из памяти

ТЗ 3.6 требует, чтобы аналитик мог подтверждать и отклонять выводы. Само по
себе проставление отметки мало что даёт — важно последствие: отклонённое
утверждение удаляется из долговременной памяти вместе со своими рёбрами
графа. Без этого система растиражирует ошибку: в следующей миссии отклонённый
вывод всплывёт как «результат прошлого исследования» и получит вес наравне
с проверенными фактами.

### 2.17. Кэш внешних запросов

ТЗ 9 предписывает кэшировать обращения к внешним сервисам на час. На свободных
тарифах у этого есть второй смысл, важнее скорости: суточная квота модели
выедается повторными прогонами по одной теме, а поисковые API отвечают 429
на частые повторы. Кэшируются и ответы модели (при низкой температуре они
почти детерминированы), и выдача каждого поискового движка — включая пустую:
повторять заведомо безрезультатный запрос к движку с лимитами бессмысленно.

Хранилище — в памяти процесса. ТЗ называет Redis; переход на него делается
вместе с переходом на Celery и затрагивает только `app/cache.py`.

## 3. Отступления от ТЗ

| ТЗ | Реализация | Причина | Стоимость возврата к ТЗ |
|---|---|---|---|
| Celery + Redis | asyncio в процессе | MVP должен запускаться одной командой | контракт задачи совпадает с ТЗ 14.1; меняется `_run_task` |
| PostgreSQL + pgvector | SQLite по умолчанию | нулевая установка | `DATABASE_URL`; косинус заменяется оператором pgvector в `memory/store.recall` |
| WeasyPrint | WeasyPrint → браузер → ReportLab | WeasyPrint требует GTK вне pip (Windows) | WeasyPrint подхватывается автоматически, если установлен |
| React + TS + Vite | HTML + JS одной страницей | этап 10 плана ТЗ | интерфейс изолирован в `app/web/` |
| USPTO / Espacenet | поиск по `patents.google.com` | обе базы требуют ключей | добавляется движок в `search/engines.py` |

## 4. Производительность

Требования ТЗ 9 (сложный запрос ≤ 5 мин, 50 сессий) обеспечиваются:

* параллельным выполнением уровней DAG (`MAX_CONCURRENT_AGENTS`, по умолчанию 8);
* веерным опросом движков поиска одним `asyncio.gather`;
* таймаутами на агента (`AGENT_TIMEOUT`) и на миссию (`MISSION_TIMEOUT`);
* семафором одновременных миссий (`MAX_CONCURRENT_MISSIONS`).

Блокирующие операции — matplotlib, python-docx, xhtml2pdf, разбор PDF — вынесены
в `asyncio.to_thread`, чтобы не удерживать event loop.
