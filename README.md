# Ищейка (Sleuth)

Мультиагентная система поиска, анализа, прогнозирования и риск-оценки технологий,
изделий и научно-исследовательских работ. Реализация по ТЗ редакции 4.0
([docs/ТЗ-Ищейка.txt](docs/ТЗ-Ищейка.txt)).

Один запрос система воспринимает как **миссию**: декомпозирует её, параллельно
запускает специализированных агентов, проверяет собранные факты, подвергает выводы
критике и опровержению и только затем синтезирует отчёт с прогнозом, картой рисков
и честно посчитанным уровнем достоверности.

```
Запрос → Память → Декомпозиция → DAG → Параллельный поиск и анализ
      → Аудит источников → Критика и Red Team → Уверенность
      → Синтез (Judge) → Отчёт HTML/DOCX/PDF → Память
```

## Что работает сейчас

| Возможность | Статус |
|---|---|
| 13 агентов W01–W13 | реализованы все |
| Поиск по открытым источникам | OpenAlex, Crossref, arXiv, PubMed, Semantic Scholar, DuckDuckGo, патенты — **без ключей**; Google CSE, SerpAPI, Bing, SearXNG — по ключу или своему инстансу |
| Оркестратор DAG | параллельные уровни, таймауты, до 3 повторов с экспоненциальной задержкой |
| Форсайт | подгонка S-кривой, 3 сценария на горизонты 1–20 лет, доверительные интервалы |
| Риски | 5 типов, матрица 5×5, экспозиция, меры снижения |
| Достоверность | ссылка и дата у каждого факта, авторитетность издателя по префиксу DOI, цитируемость, итоговая уверенность по 5 факторам |
| Взаимная проверка | Evidence Auditor, Critic, Red Team, выявление противоречий |
| Отчёты | HTML, DOCX, PDF с графиками (PDF — через WeasyPrint, браузер или ReportLab) |
| Память | семантический поиск по прошлым миссиям, автосохранение выводов, граф связей supports/contradicts/derived_from |
| Документы пользователя | загрузка PDF/DOCX/TXT, текст идёт агентам наравне с найденными источниками и попадает в перечень источников отчёта |
| Human-in-the-loop | подтверждение и отклонение выводов; отклонённый удаляется из памяти |
| Кэш | результаты поиска и ответы модели кэшируются на час — экономия суточной квоты |
| API | REST + WebSocket-поток событий, JWT, RBAC, rate limiting, аудит, повторный запуск миссии |
| Интерфейс | встроенная веб-страница: запуск, живой прогресс, история, скачивание, проверка выводов |
| Предметные области | восемь профилей под задачи телеком-компании: подсказки терминов планировщику и готовые формулировки в форме |
| Установщики | Windows (exe, без установки Python) и Android (APK) |

## Быстрый старт (из исходников)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows;  source .venv/bin/activate — Linux/macOS
pip install -r requirements.txt
copy .env.example .env            # cp .env.example .env — Linux/macOS
uvicorn app.main:app --reload
```

Открыть <http://localhost:8000> — веб-интерфейс, <http://localhost:8000/docs> — Swagger.

Первый зарегистрированный пользователь автоматически получает роль администратора.

### Ключи LLM

Без ключа система поднимется и пройдёт весь конвейер, но на **заглушке**: отчёт будет
демонстрационным и помечен соответствующей плашкой. Проверить настройку:

```bash
python tools_check_llm.py
```

**Бесплатные варианты (банковская карта не нужна):**

| Провайдер | Где получить ключ | Свободный тариф |
|---|---|---|
| **Groq** | console.groq.com → API Keys | ~30 запросов/мин, Llama 3.3 70B, самый быстрый |
| **Google Gemini** | aistudio.google.com/apikey | ~1500 запросов/сутки |
| **OpenRouter** | openrouter.ai/keys | модели с суффиксом `:free`, ~50 запросов/сутки |
| **Ollama** | локально, ключ не нужен | без лимитов; на машине без GPU медленно |

```ini
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_...
GROQ_MODEL=openai/gpt-oss-120b
```

**Про лимиты бесплатных тарифов.** Они считаются не в запросах, а в токенах
в минуту: у Groq это 8000 TPM. Полная миссия из тринадцати агентов тратит около
30 000 токенов, поэтому система ведёт учёт бюджета (`llm/ratelimit.py`) и
выдерживает паузы — иначе половина агентов падает с 429. Практическое следствие:
на бесплатном тарифе миссия идёт 5–8 минут вместо полутора. Настраивается
через `LLM_TOKENS_PER_MINUTE`; фактический лимит система уточняет сама
по заголовкам ответа провайдера.

**Платные:** `deepseek`, `qwen`, `openai`, `anthropic` — бесплатных кредитов не дают
(у DeepSeek нулевой баланс отвечает `HTTP 402 Insufficient Balance`).

Поисковые движки из списка по умолчанию ключей не требуют вовсе.

## Пример использования

```bash
TOKEN=$(curl -s -X POST localhost:8000/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"analyst","password":"secret-pass"}' | jq -r .access_token)

curl -X POST localhost:8000/api/v1/missions \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"query":"Оцени перспективы твердотельных аккумуляторов","mode":"comprehensive","horizons":[1,3,5,10]}'

curl "localhost:8000/api/v1/missions/<id>/report?fmt=docx" \
  -H "Authorization: Bearer $TOKEN" --output report.docx
```

Режимы: `quick` (6 агентов), `forecast`, `risk`, `comprehensive` (все 13).

## Поиск: что работает без ключей

| Движок | Ключ | Что даёт |
|---|---|---|
| OpenAlex | не нужен | ~250 млн работ, число цитирований, издатель |
| Crossref | не нужен | метаданные по DOI, цитируемость |
| Semantic Scholar | не нужен | аннотации, цитируемость (общий лимит, бывает занят) |
| arXiv | не нужен | препринты |
| PubMed | не нужен | биомедицина |
| DuckDuckGo | не нужен | общий веб — **нестабилен**, см. ниже |
| Google CSE / SerpAPI / Bing | нужен | общий веб стабильно |
| SearXNG | свой инстанс | метапоиск по Google/Bing/DDG сразу |

Все движки опрашиваются параллельно, с индивидуальными паузами под лимиты каждого API,
результаты дедуплицируются и **ранжируются по релевантности запросу** — авторитетный
источник не по теме хуже среднего, но по теме.

### Ограничение: общий веб-поиск

DuckDuckGo при частых запросах отвечает антибот-заглушкой, а с некоторых адресов —
403. Система распознаёт это, делает повтор и пишет отказ в журнал явным текстом.
Научные базы не затронуты. Для новостей, рынка и отраслевых отчётов нужен ключ
Google CSE или SerpAPI, либо свой инстанс SearXNG — интеграции написаны,
включаются строкой в `.env`.

## Отклонения от ТЗ (осознанные)

| ТЗ | Реализовано | Почему |
|---|---|---|
| Celery + Redis | asyncio в процессе | MVP запускается одной командой; контракт задачи совпадает с ТЗ 14.1, замена исполнителя локальна |
| PostgreSQL + pgvector | SQLite по умолчанию | `DATABASE_URL` переключает на PostgreSQL без правки кода; косинус считается в Python |
| WeasyPrint | WeasyPrint → headless-браузер → ReportLab | WeasyPrint на Windows требует GTK вне pip. xhtml2pdf проверен и отвергнут: на Windows он не передаёт TTF в reportlab и молча печатает кириллицу пустыми плашками |
| React + Vite | одностраничный HTML/JS | этап 10 по плану ТЗ; текущий интерфейс закрывает критерии MVP |
| USPTO / Espacenet | патентный поиск через `patents.google.com` | обе базы требуют ключей; адаптеры подключаются как отдельные движки |
